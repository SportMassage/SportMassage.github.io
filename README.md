# SportMassage.github.io

Static landing page for a massage and kinesiotaping practice in Warsaw (Mokotów). It is hosted on GitHub Pages, with a custom domain set in `CNAME`. There is no backend.

## Run locally

The stylesheet `assets/css/tailwind.min.css` is **generated and not committed**, so build it once after cloning (requires Node.js):

```
npm install
npm run build
```

Then open `index.html` in a browser (`start index.html` on Windows), or serve the folder, which is closer to how GitHub Pages behaves:

```
npx serve .
```

While editing markup or styles, keep the CSS rebuilding automatically in a second terminal:

```
npm run watch
```

Fonts (Manrope) and icons (inline SVG) are self-hosted. The only third-party requests are Google Analytics (after you accept the consent banner) and the Google Maps iframe (after you click "Pokaż mapę"). Once you accept analytics, GA4 also fires from `localhost`, so your own test clicks can show up.

## Deploy

Deploys are **manual**; pushing to `main` does not publish anything. To publish: open the repository on GitHub, go to **Actions → Deploy to GitHub Pages → Run workflow**, and pick `main`. The workflow (`.github/workflows/deploy.yml`) runs `npm ci` and `npm run build`, then publishes `index.html`, `privacy.html`, `assets/`, `robots.txt`, `sitemap.xml` and `CNAME` to GitHub Pages.

One-time setup: in the repository go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**. Do this *before* merging the workflow into `main`. The old "Deploy from a branch" mode would serve the site without CSS, because the CSS is no longer in git.

## Styles (Tailwind)

- `assets/css/style.css` is the Tailwind input (plus a few custom classes).
- `tailwind.config.js` holds the colour tokens. Use `bg-theme-base`, `text-theme-muted` and so on instead of hex values.
- Keep body text at 14px or larger (`text-sm`+) and interactive elements at least 44px tall (`min-h-11`).
- Tailwind only emits classes it finds in `index.html`, `privacy.html` and `assets/js/*.js`, so rebuild (or run `watch`) after adding a new class.

## Content and translations

All copy lives in two places that must stay in sync:

1. `index.html`: each translatable element has `data-i18n="<key>"`, and its inline text is the Polish fallback.
2. `assets/js/translations.js`: the `i18n` object with `pl`, `ua`, `ru` and `en` blocks. Add or change the key in **all four**.

`assets/js/app.js` picks the language from `localStorage`, then the browser language, then falls back to `pl`. It also handles the cookie-consent banner (GA4 loads only after the visitor accepts), the click-to-load map, and GA4 click events (WhatsApp, Telegram, phone) by matching link URLs, so update the matchers there if you change those links.

## Structure

```
index.html                    the whole page (also SEO, JSON-LD, Consent Mode defaults)
privacy.html                 privacy policy (same i18n mechanism)
assets/css/style.css          Tailwind input
assets/css/tailwind.min.css   generated by npm run build (git-ignored)
assets/js/translations.js     i18n strings
assets/js/app.js              language switcher, mobile menu, analytics events
assets/img/                   photos
assets/fonts/                 self-hosted Manrope (woff2, SIL OFL)
tailwind.config.js            theme colours and content paths
.github/workflows/deploy.yml  build + deploy to GitHub Pages
robots.txt, sitemap.xml, CNAME
```
