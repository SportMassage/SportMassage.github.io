# SportMassage.github.io

Static landing page for a massage and kinesiotaping practice in Warsaw (Mokotów). It is hosted on GitHub Pages, with a custom domain set in `CNAME`. There is no backend.

## Run locally

The stylesheet `assets/css/tailwind.min.css` and the whole `_site/` folder are **generated and not committed** (requires Node.js 22, see `.nvmrc`; CI uses the same version):

```
npm install
npm run build
npx serve _site
```

`npm run build` builds the CSS and then generates one page per language into `_site/`: `/` (Polish), `/uk/`, `/ru/` and `/en/`, each with its own `privacy.html`, plus `sitemap.xml`. Serve `_site`, not the repo root: the repo-root `index.html` and `privacy.html` are only the Polish **templates** (opening them directly works as a Polish preview, but they have no `hreflang`, no other languages and no sitemap).

After editing markup or copy, run `npm run build` again. While editing styles, keep the CSS rebuilding in a second terminal (it does not regenerate the pages):

```
npm run watch
```

Fonts (Manrope) and icons (inline SVG) are self-hosted. The only third-party requests are Google Analytics (after you accept the consent banner) and the Google Maps iframe (after you click "Pokaż mapę"). Once you accept analytics, GA4 also fires from `localhost`, so your own test clicks can show up.

## Deploy

Deploys are **manual**; pushing to `main` does not publish anything. To publish: open the repository on GitHub, go to **Actions → Deploy to GitHub Pages → Run workflow**, and pick `main`. The workflow (`.github/workflows/deploy.yml`) runs `npm ci` and `npm run build`, then publishes the generated `_site/` folder to GitHub Pages.

One-time setup: in the repository go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**. Do this *before* merging the workflow into `main`. The old "Deploy from a branch" mode would serve the site without CSS, because the CSS is no longer in git.

## Styles (Tailwind)

- `assets/css/style.css` is the Tailwind input (plus a few custom classes).
- `tailwind.config.js` holds the colour tokens. Use `bg-theme-base`, `text-theme-muted` and so on instead of hex values.
- Keep body text at 14px or larger (`text-sm`+) and interactive elements at least 44px tall (`min-h-11`).
- Tailwind only emits classes it finds in `index.html`, `privacy.html` and `assets/js/*.js`, so rebuild (or run `watch`) after adding a new class.

## Content and translations

All copy lives in two places that must stay in sync:

1. `index.html` and `privacy.html`: each translatable element has `data-i18n="<key>"`, and its inline text is the Polish fallback. `data-i18n-<attr>="<key>"` translates an attribute instead (`alt`, `title`, `content` of meta tags).
2. `i18n/translations.js`: the `i18n` object with `pl`, `ua`, `ru` and `en` blocks. Add or change the key in **all four**.

`scripts/build-site.mjs` (run by `npm run build`) fills a copy of each template per language and fails the build if a key is missing in any locale. It also sets `<html lang>`, the title, meta/Open Graph tags, JSON-LD, `canonical` and `hreflang` links, and writes `sitemap.xml`. Ukrainian is `ua` in the code and in `localStorage`, but its URL and `hreflang` are `uk`.

`npm run check:i18n` runs only that validation (no build, no CSS needed) and is stricter: it also fails when the inline Polish text in a template differs from `pl`. Run it after editing copy.

There is no runtime translation. `assets/js/app.js` shows a dismissible banner that suggests the page in the visitor's saved or browser language (it never redirects), and stores an explicit language choice in `localStorage`. It also handles the cookie-consent banner (GA4 loads only after the visitor accepts), the click-to-load map, and GA4 click events (WhatsApp, Telegram, phone) by matching link URLs, so update the matchers there if you change those links.

## Structure

```
index.html                    Polish template of the whole page (also SEO, JSON-LD, Consent Mode defaults)
privacy.html                 Polish template of the privacy policy
i18n/translations.js          i18n strings (pl, ua, ru, en); not shipped to the browser
scripts/build-site.mjs        generates _site/ (all languages, sitemap.xml)
assets/css/style.css          Tailwind input
assets/css/tailwind.min.css   generated by npm run build (git-ignored)
_site/                        generated by npm run build (git-ignored), this is what gets deployed
assets/js/app.js              language suggestion banner, mobile menu, consent, analytics events
assets/img/                   photos
assets/fonts/                 self-hosted Manrope (woff2, SIL OFL)
tailwind.config.js            theme colours and content paths
.github/workflows/deploy.yml  build + deploy to GitHub Pages
robots.txt, CNAME           copied into _site/ as they are (sitemap.xml is generated)
```
